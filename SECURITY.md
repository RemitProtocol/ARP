# Security Policy

## Supported Versions

The Agent Remittance Protocol (ARP) maintains active security support for the following versions:

| Version | Supported          | Notes                                      |
| ------- | ------------------ | ------------------------------------------ |
| v0.1.x  | :white_check_mark: | Current Beta release. Actively maintained. |
| < v0.1  | :x:                | Unsupported prototype releases.            |

## Reporting a Vulnerability

We take the security of our non-custodial routing layer and AI-agent isolation mechanisms very seriously. If you discover a vulnerability, **do not open a public issue.** 

Please report all security vulnerabilities via email to:
**security@remitprotocol.com**

In your report, please include:
- A description of the vulnerability and its potential impact.
- Detailed steps to reproduce the issue.
- Any relevant logs, test cases, or code snippets.
- Your contact information for follow-up.

## Disclosure Process

We follow a structured and institutional vulnerability management process aligned with Web3 best practices:

1. **Acknowledgement (48 Hours):** You will receive a confirmation that our security team has received your report within 48 hours.
2. **Triage & Assessment (7 Days):** Our core security engineers will reproduce the issue, determine its severity, and decide on a mitigation strategy within 7 days.
3. **Patch & Mitigation (30 Days):** We commit to developing, testing, and deploying a secure patch for confirmed vulnerabilities within 30 days of triage.
4. **Public Disclosure:** Once the fix is verified and deployed to mainnet/production environments, we will publicly disclose the vulnerability (with credit to the security researcher, if desired).
